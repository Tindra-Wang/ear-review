# 听见 · 蓝牙耳机评论分析系统

一个以自然语言处理为核心的本地 Web 系统：输入中文评论，识别六项评价方面，判断各方面情感，并高亮真实原文；进一步汇总产品画像、比较产品并人工复核。

## 启动

需要 Node.js 24.14 或更高的 24.x 版本。当前项目依赖已安装、构建已完成。

在项目目录运行：

```powershell
npm install
npm run build
npm start
```

最方便的方法是双击项目内的 `启动系统.bat`：依赖或构建缺失时自动准备，启动就绪后自动打开网页。首次准备依赖需要网络。服务运行时保留启动窗口，Ctrl+C 停止。

再次双击时自动识别已有听见服务，直接打开 http://127.0.0.1:3001 并正常退出，不再重复打开数据库。若是其他程序占用端口，会提示在 .env 中改 PORT。旧的 .cmd 入口仅作为兼容启动器保留。

启动器会等待系统就绪，再请求默认浏览器打开页面，并保留提示窗口。如果浏览器未显示，直接复制窗口中的 URL 打开。诊断日志位于 `data/runtime/launcher.log`；自动打开失败时会显示错误，不再静默关闭。

修改开发代码时用 `npm run dev`，前端为 http://127.0.0.1:5173，API 为 3001；先停止已运行的生产服务，避免端口冲突。

## 管理员

- 账号为 `admin`。
- 首次运行生成随机密码，保存在 `data/runtime/admin-password.txt`。打开该文件查看，不在界面或日志暴露密码。
- 也可首次启动前复制 `.env.example` 为 `.env`，设置 `ADMIN_PASSWORD`。已有数据库时此变量不会覆盖原密码。
- 会话仅保存在当前浏览器标签页会话中，八小时过期。服务重启后重新登录。
- 系统仅监听本机 127.0.0.1；不要把本地演示配置直接当作公网部署方案。

## 四个页面

1. 评论分析：六项方面、正负中性/混合、未提及/待复核、证据高亮；支持学习模型与纯规则对照。
2. 产品画像：评价分布、样本量、筛选、关键词搜索、分页、人工复核及原始模型视图。
3. 产品对比：两到三款产品按通勤/游戏/长时间佩戴关注维度比较，可展开原文；缺失证据不补分。
4. 数据工作台：管理员登录、产品创建/编辑、CSV 校验与去重、持久化导入、Worker 分析任务及失败重试。

## 数据真实性

预置三款虚构产品和 36 条人工教学评论；训练语料 126 条；独立编写的教学检查集 24 条。它们不是真实用户数据，页面和评估文件都明确标识。检查集分数不能用于宣称真实耳机评论分析准确率。

目前没有取得独立授权的真实耳机方面级标注集。系统可导入有权限使用的真实 CSV；报告必须如实说明数据来源及这一限制。

导入字段：`productId,reviewId,text,source`。先创建产品，再使用该产品 ID。必填前三项，每条最多 1000 字、每批 5000 行、文件 5 MB。产品和标准化文本指纹共同去重。同一条评论的同一方面最多计一次。预览 15 分钟过期；正文或来源改动后重新预览。

人工复核需提供原文真实子串与理由，修订和原预测分开保存。正面占比的分母为正面、负面、中性、混合的已判定评论数；待复核和未提及不进入分母。20 条只是提示阈值，不是统计显著性证明。

## NLP 与训练

规则分句与转折切分 → 固定方面词典定位 → 局部上下文字符 1/2/3-gram → 多项式朴素贝叶斯 → 领域情感规则优先校验 → 同方面意见聚合 → 原文 UTF-16 偏移保存。

完整数据来源候选、CSV 整理步骤、训练公式、技术资源与开发过程见 docs/NLP实现、数据来源与从零开发说明.md。当前没有调用多模态模型或在线大模型；导入 CSV 不会自动训练。预置语料是在开发中编写的合成样例，本次由助手撰写，不能描述成已经爬取或人工访谈采集的消费者数据。

规则能明确判断时优先使用规则；无明确规则时采用 MNB 候选，低分类间隔或难以归属时待复核。系统没有把整句情感复制到多个方面，也没有接入在线大模型。该混合方法是课程可运行基线，不能宣称已采用深度学习。

```powershell
npm run train
npm run evaluate
```

导出 `data/model.json`，服务和 Worker 会读取并校验该模型；没有文件时使用内置教学训练语料。重新训练后重启服务，新版本可重新分析旧批次，旧预测仍保存。

真实训练数据可以另行标注为 CSV（`aspect,text,label`），其中方面使用 sound/noise/comfort/battery/call/latency，情感使用 positive/negative/neutral。仅输入训练划分，不加入验证/测试集：

```powershell
npm run train -- --data data/authorized-train.csv --kind "授权真实训练集"
```

外部数据使用条件由提供者核实。现有 `evaluate` 默认检查集仍为教学集，不能因为换了训练集就当作真实领域评估。真实独立测试需另行构造并记录标注、划分和类别支持数。

```powershell

```

18 项核心/存储/启动测试，4 项浏览器及 API 端到端场景。端到端测试要求本机 Chrome，使用独立 3002 端口和独立测试数据库，不写演示数据库。`benchmark` 需启动 3001 服务，仅进行查询与进程内分析冒烟测量。

截图及端到端结果位于 `output/playwright/`；算法结果位于 `data/evaluation.json`；性能结果位于 `data/benchmark.json`。截图由实际页面生成。

## 实现与方案的裁剪

- 使用 Vue 自带响应式状态与路由，未引入 Pinia/Element Plus，减少表单和页面依赖。
- 使用 Node 内置 SQLite 与参数化 SQL代替 Prisma，数据库 schema 在 `store.ts` 中初始化；本地环境 Node 24.14 会输出 SQLite 实验性提示，后续若要求长期生产运行可替换适配层。
- 评价分布用有文字计数的堆叠条实现，未引入 ECharts。
- 不包含实时爬虫、BERT 微调、自动场景推断、商业总排名或完整真实领域性能实验。

上述裁剪保留了 P0 的核心功能闭环。报告中不能沿用方案写成“已经使用 Prisma、ECharts 或深度模型”。

## 目录

`apps/web`：Vue 界面；`apps/api`：NestJS 接口、鉴权、SQLite 与 Worker；`packages/contracts`：共享类型；`packages/nlp`：分类器和规则；`scripts`：训练/评价/性能脚本；`data`：教学数据、模型和评价；`docs`：工程说明与报告底稿。

关闭终端或 Ctrl+C 可停止服务。运行数据在 `data/runtime/`，请备份数据库及模型；不要把含密码的运行目录提交到仓库。
