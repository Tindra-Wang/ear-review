# 真实CSV闭环与浏览器辅助采集

记录日期：2026-10-13。本文件记录实际执行结果和新增功能，公开语料不用于替代华为FreeClip的专属评论。

## 1. 数据来源与筛选

来源：[SetFit/amazon_reviews_multi_zh](https://huggingface.co/datasets/SetFit/amazon_reviews_multi_zh)。使用本地已有的200000条原始JSONL缓存，关键词筛出154条蓝牙耳机候选。按来源label五组各至多10条，以原评论ID的SHA256排序固定抽取50条，再逐条阅读剔除10条明显非目标对象的评价，保留40条原文。不是本项目生成评论，也未核验每条购买真实性。

来源label仅保留在CSV的sourceLabel列，不是六方面情感金标准。按来源标签分组抽样及人工筛选会改变分布，不能据此推断市场好评率。评论的具体型号不能可靠恢复，因此集合名为“公开蓝牙耳机评论集合（型号未知）”，禁止作为FreeClip或其他单一型号推荐依据。

CSV：[bluetooth-reviews-real-40.csv](../data/raw/bluetooth-reviews-real-40.csv)，SHA256=a1e4f94b9b4bdba9063fdceb93e32a24e02e03cf551bab4b0e8ba28be2e8abd7。来源记录、原文件hash及全部入选/剔除ID见[真实CSV数据来源.json](实验结果/真实CSV数据来源.json)。

## 2. 实际数据库和模型流程

脚本scripts/import-real-csv.ts通过真实REST接口登录、建集合、预览CSV、提交导入、建立semantic任务，轮询任务并读取画像和总结。数据库集合ID=real-bluetooth-corpus，批次=3，首轮任务=2，absa-v3复测任务=4，absa-v4复测任务=5。未直接向数据库填入预制预测。

40条评论入库，synthetic=0。同一40条原文：absa-v2首轮23条成功、17条失败；absa-v3复测32条成功、8条失败，当时汇总34条含2条保留v2结果；absa-v4复测40条成功、0条失败，任务completed，当前全部40条为v4结果。没有静默切换规则/MNB。任务的processed表示已尝试数，不是成功数。

成功预测按评论/版本保存，错误进入job_errors；总览显示未成功分析数，分布只基于已判定的方面意见。不同方面可以有不同分母，待复核另计。没有人工方面真值，所以不报告此数据的准确率或F1。

最新v4真实结果见[真实CSV闭环验证.json](实验结果/真实CSV闭环验证.json)，历史归档见[v2](实验结果/真实CSV闭环验证-absa-v2.json)、[v3](实验结果/真实CSV闭环验证-absa-v3.json)。重跑脚本会复用已导入批次；失败任务可以创建重试，但同版本重试会更新其预测。

### 2.1 为什么CSV分析失败，修复了什么

CSV解析、列映射和SQLite导入都成功。首轮17条失败发生在模型返回后的协议校验：10条证据格式无效，4条证据不属于原文，2条未知或重复方面，1条生成长度达到上限。复现记录见[失败输出诊断.json](实验结果/失败输出诊断.json)：其中一条输出了有效音质意见，同时为未提及的其他方面补了空证据占位；整条返回因此被拒绝。不能据这一例断言所有格式错误都同因。

修改packages/nlp/semantic.ts，将提示版本升级为absa-v3：仅输出原文涉及的方面，允许opinions为空，禁止未提及方面占位；约束证据和理由长度；第一次格式/证据/方面校验失败时，把具体错误反馈给模型，最多再生成一次，两次共用180秒截止时间。网络或服务错误不做此纠错重试。仍使用相同Qwen3:4b预训练权重，没有微调或更换模型。

复测输出通过校验比例从23/40（57.5%）提高到32/40（80%）；这是输出可用率，不是情感准确率。剩余8条中7条仍生成原文不存在的证据，1条返回未知或重复方面，均已记录并保留原评论。没有放宽原文子串校验，也没有把失败当作中性意见。需要人工核对模型成功输出；证据在原文中也不代表情感判断一定正确。

### 2.2 absa-v4实际修复与验证

已实现片段编号协议：服务端按中文/英文句号、问号、感叹号、逗号、分号和换行切分原文，超过120个Unicode字符的连续片段再拆分，保留原字符与UTF16起止位置。输入同时包含完整评论及S1、S2等编号片段，模型按完整上下文判断方面和情感，只选择spanId，不再生成证据正文。JSON schema中spanId枚举取自本条原文；服务端再次验证ID并还原原文证据，拒绝不存在的编号。新协议opinions为六个固定方面键组成的对象，省略未提及键，避免数组重复方面。仍保留标签、证据和状态校验以及最多一次纠错重试。

同一40条真实原文实际通过本地Qwen3分析，任务5完成：40/40输出成功、0失败、40条均为v4；所有保存证据的原文切片校验通过。输出可用率为100%，没有方面级人工金标准，不能称为100%情感准确率，也不保证其他CSV零失败。片段证据粒度较粗，选择原文片段仍可能归属或情感判断错误。Qwen3权重没有重新训练；历史42条模型对照报告仍对应v2，不能把其F1套用于v4。

任务页面默认仅显示各批次最新任务；可展开历史任务。旧v2的17条失败和v3的8条失败保留追溯，不会冒充当前任务失败。进度明确标注“已尝试”，历史任务不提供重试按钮。

## 3. 持久化Chrome浏览器自动采集（无需扩展/配对码）

用户要求取消扩展及配对流程，生产实现现为原生Google Chrome启动加Playwright的CDP连接。系统使用固定的data/runtime/chrome-collector-profile专用配置目录，而非每次新建临时浏览器上下文；从连接后的默认上下文读取页面，不再创建空登录态的新context。配置目录保留该采集浏览器的登录态，不复制或接管用户日常Chrome的配置文件。首次正常登录/验证和后续登录过期时需用户操作。

启动参数仅包含固定专用配置目录、本机调试端口、初次运行提示选项和商品URL；不采用隐藏自动化标志、代理轮换或验证码绕过。调试服务使用127.0.0.1和临时端口，不对公网开放。系统仅关闭自己启动的采集专用Chrome；不会关闭日常Chrome。数据目录与登录态不提交Git。

用户流程：填写商品URL → 打开Chrome辅助采集 → 首次正常登录或完成页面验证 → 开始自动采集。系统尝试点击评价标签，等待评价区，提取可见评论节点并去重，寻找下一页或滚动新版评价弹窗加载，最多10次加载/100条，每页间隔1.5秒；达到条数上限、无新评论或找不到可用下一页时停止并生成实际已得CSV。可另用“读取当前评论页”配合手动翻页，最后结束生成CSV。只有实际评论节点会被读取，不把广告整页文本当评论。

## 4. 状态、接口与实测边界

POST /api/collections的method=browser打开采集Chrome；POST /api/collections/:id/read读取当前页；POST /api/collections/:id/auto在后台自动读取/翻页并将进度回写collections；POST /api/collections/:id/finish结束手动采集。全部写接口仍需本机管理员登录。已删除扩展目录、配对码入口与无管理员令牌的visible接收接口。

自动采集期间状态running，用户不能并发启动另一任务。首次无可读取评论或页面验证时回到waiting并显示原因，窗口保留，允许登录/打开评价区后再点击自动采集。已读取评论不断保存，失败不丢已有CSV。20分钟到期或专用窗口关闭后已有结果保留，状态partial或blocked；后台重启未完成任务标失败，配置登录态仍在专用目录。CSV需用户核对并确认导入才进入正式评论和NLP分析。

用户正常浏览器能访问京东，旧自动化临时会话曾被拦截，具体平台规则未知。历史原生Edge实测曾正常打开商品https://item.jd.com/100239311413.html（华为FreeClip 2），采得3条真实评论，CSV为data/raw/jd-freeclip2-100239311413-real.csv，记录归档为实验结果/京东浏览器自动采集实测-Edge.json。用户随后要求改Chrome，当前生产固定使用Chrome CDP。Chrome任务7首次打开商品后跳转passport.jd.com正常登录页；用户完成登录后，同一会话实际读取完整评价弹窗并滚动加载，采集50条去重评论，任务completed、error=null。真实CSV为[data/raw/jd-freeclip2-chrome-100239311413-real.csv](../data/raw/jd-freeclip2-chrome-100239311413-real.csv)，实际任务记录见[京东浏览器自动采集实测.json](实验结果/京东浏览器自动采集实测.json)，行数、原文去重及SHA256见[京东真实CSV校验.json](实验结果/京东真实CSV校验.json)。采集CSV保存在collections表，可在平台采集页下载或预览并导入；尚未将这50条作为新的正式评论批次运行NLP分析。平台当前排序的50条不是随机或全量样本，不能推断总体好评率，也不等同于本项目独立核验购买真实性。

## 5. 开发与复现

npm run data:real可重跑真实CSV导入/分析脚本。生产采集仍使用Playwright，但通过CDP连接系统Chrome，未使用chromium.launch创建临时生产会话。无需Python或安装扩展。专用浏览器配置位于data/runtime/chrome-collector-profile；不要上传此目录或在其运行时删除目录。

核心测试在真实原生Chrome中连接CDP，验证可见DOM提取、去重、自动点击下一页、条数上限、拒绝其他商品，以及关闭重开后localStorage保存；页面为受控夹具，不是京东采集结果。接口测试验证自动进度/CSV写入及完成状态；端到端验证Web入口与导入衔接。
