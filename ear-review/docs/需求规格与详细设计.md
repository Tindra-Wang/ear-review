# 需求规格与详细设计（实现基线 v1.0）

日期：2026-10-12。范围：中文耳机评论分析课程 Web 系统。本文件描述已实现版本，和实施前方案的裁剪差异见 README。

## 1. 业务目标与系统边界

普通浏览者通过评论中的具体方面理解耳机优缺点；管理员维护产品、导入评论、运行分析并修订错误。核心能力为固定方面类别识别、局部情感分类、原文证据定位。系统不执行真实声学测评，不进行电商交易、实时爬虫或开放式问答。

六个方面：音质 sound、降噪 noise、舒适度 comfort、续航 battery、通话 call、游戏延迟 latency。

## 2. 功能规格与追踪

FR-01：访客只读浏览，管理员使用账号密码登录后执行写操作；创建和编辑产品。输入为产品 ID、名称、说明；重复 ID 和非法 ID 返回 400，未登录写操作返回 401。对应 Auth、Products 接口；端到端测试“API 鉴权”及“管理员页面”验证。

FR-02：输入 UTF-8 CSV 与来源说明，预览有效、错误和重复行。必填 productId/reviewId/text，最多 5000 行、5 MB、每条 1000 字。产品不存在、空评论、缺列和错误引号不静默接收。确认后事务提交有效非重复记录；持久化批次校验数量与拒绝行原因。对应 Imports、Store；存储去重测试及 API 导入测试验证。

FR-03：单条分析不写正式统计；批次分析持久化任务状态并由 Worker 执行。任务正常状态 queued → running → completed，异常变 failed；重复请求已有成功/运行任务返回原任务；失败可建立新的重试任务。重新启动时未完成任务改为 failed 并提示原因。对应 AnalysisJobs；Worker 端到端、幂等和重启测试验证。

FR-04：输入中文文本，输出方面、正面/负面/中性/混合、classified/review 状态、证据和版本。每条证据必须为原文子串，索引为 UTF-16 左闭右开。未提及不生成预测；多方面意见难以归属时待复核。对应 Nlp 和 AnalysisResult；11 项 NLP 单元测试及桌面原文定位测试验证。

FR-05：按产品、方面、情感、关键词、待复核/已复核筛选，8 条一页。管理员修订方面与情感时填写真实原文证据和理由。修订不覆盖预测，历史保存 actor/time/reason。对应 Reviews、Corrections；存储有效/纯模型视图、API 伪造证据拒绝、浏览器复核测试验证。

FR-06：每个方面统计正面、负面、中性、混合、待复核与修订数。同评论同方面最多计一次。N=正面+负面+中性+混合，正面占比=正面/N；N=0 为 null，N<20 提示样本不足。待复核和未提及不进入 N。对应 Statistics；混合计数、空数据和修订一致性测试验证。

FR-07：选择 2～3 个产品比较同一维度评价与原文。通勤突出 noise/comfort，游戏突出 latency/sound，长时佩戴突出 comfort/battery；全部模式显示六项。缺失数据不填零，不生成总排名。对应 Comparison；产品画像/需求对比浏览器测试验证。

FR-08：管理员导出筛选结果。CSV 包含来源、教学标记、方面、状态、证据、模型版本和修订标记。没有方面的评论在未指定方面筛选时保留空方面行；类公式单元格前置单引号，防止表格软件执行。对应 Exports；API 和浏览器下载测试验证。

## 3. 关键用例

### UC-01 导入与分析

参与者：管理员。前置：已登录，产品存在。

主流程：准备 CSV → 填写来源和教学标记 → 校验预览 → 确认有效记录 → 事务入库 → 创建任务 → Worker 分析 → 保存预测 → 显示完成状态。

替代/异常：文件超限或格式错误直接拒绝；错误与重复行跳过并记录；没有有效行不可提交；预览过期需重做；分析失败可重试；成功提交后不能重复使用预览标识。

后置：评论、批次、校验概要、模型版本预测和任务进度可以查询。

### UC-02 看画像与对比

参与者：浏览者。前置：产品存在。

主流程：选产品 → 看六方面分布 → 点击方面筛选 → 看高亮原文 → 进入对比 → 选至少两个产品 → 选择需求 → 展开证据。

异常：无评论时显示空数据；少于 20 条提示样本不足；选择数量不足时提示补选。后置：用户知道结论对应的评论数量及原文，系统不代替真实测试。

### UC-03 人工复核

参与者：管理员。前置：评论已分析。

主流程：打开复核 → 选方面与情感 → 填写原文真实子串及理由 → 保存 → 原预测保留 → 有效画像与对比刷新。

异常：无权访问返回 401，虚构证据/非法标签返回 400。后置：修订可追踪，纯模型统计不改变。

## 4. 非功能规格

- 可运行性：Node 24.14、Windows、本地浏览器；依赖锁定，构建通过严格 TypeScript 检查。
- 可靠性：参数化 SQL、外键、事务和唯一约束；任务持久化；旧完成结果重启后保留。
- 安全性：随机初始管理员密码，scrypt 哈希，会话八小时过期；后端检查写权限；评论按文本渲染；上传限额；登录/分析限流；CSV 公式转义。
- 可用性：四个主入口、清楚的表单标签、正负情感文字、原文高亮、加载/错误/空数据状态；390px 移动布局与桌面布局验证无横向溢出。
- 性能：当前仅完成小规模冒烟测量；5000 条数据库、不同普通电脑及端到端千条批次尚未作为已达标结论。

## 5. 详细设计

### 5.1 分层与调用

Vue 页面使用共享 contracts 调 REST API；Nest Controller 完成鉴权、参数验证和编排；Store 管理参数化 SQL/事务；Node Worker 调用 NLP 模块执行批次计算，再由主线程回写数据库。单条计算轻量，直接在接口中执行。

前端组件：App 管理路由对应页面与业务状态；AnalysisResult 展示六方面与选择高亮；EvidenceText 根据索引拆分原文；ReviewList 展示筛选结果及复核表单。请求序号防止旧查询响应覆盖新的产品选择。

### 5.2 数据字典与约束

products：id 主键，name/subtitle/source；产品名与说明可修改，ID 固定。

batches：id 主键，name/source/created_at/summary。summary 保存提交数、入库数、错误数、重复数与拒绝行原因。

reviews：id 主键，product_id 外键，external_id，text，fingerprint，source，synthetic，batch_id 外键。唯一约束为 (product_id,external_id) 与 (product_id,fingerprint)。fingerprint 由 NFKC、空白归一及 SHA-256 生成，原文不改写。

predictions：复合主键 (review_id,version)，result 保存完整 Analysis JSON，含证据偏移。重试对同一版本 upsert，统计不重复累计。

corrections：id、review_id、version、aspect、result、reason、actor、created_at。按顺序应用该版本最近修订；原预测仍存在。

jobs：id、batch_id、status、total、processed、error、version、created_at。单实例 Worker 逐任务处理；数据级幂等保证失败重试安全。

admins：username 主键、password_hash（salt:hash）。会话保存在服务器内存中，重启即失效。

数据库用 WAL，索引覆盖批次查找与复核查找。初始化兼容旧库并补充 summary 列。Schema 不支持产品删除，是本版本有意保留的数据追溯边界。

### 5.3 算法

多项式朴素贝叶斯使用字符 1/2/3-gram 频数，训练方面标记与局部上下文。类别为 positive/negative/neutral，采用加一平滑。

每类对数分数为 log P(c) + Σ count(feature) × log((类别内频数+1)/(类别总频数+词表大小))，选择最大分数。模型保存词表、类计数、样本数、来源类型与数据哈希版本。模型文件读取时检查版本格式、计数与类别有效性。

混合系统先计算 MNB 候选；明确领域情感规则优先校验。规则不覆盖时采用模型，分类分差小于 3 的未知表达进入待复核。分差只是当前教学拒判启发式，未用真实验证集校准，不能称作正确概率。

转折词将意见分开；同方面既有正面又有负面时汇总 mixed。复杂同句共享意见或无法归属进入待复核。证据是完整相关子句，不宣称达到了精细方面词级开放提取。

### 5.4 接口列表

- GET /api/health、GET /api/model：健康、模型与当前版本教学评价。
- POST /api/auth/login，GET /api/auth/me，POST /api/auth/logout：管理员会话。
- GET/POST /api/products，PATCH /api/products/:id：产品读取、创建与修改。
- POST /api/analyze：单条文本，mode=hybrid/rules。
- GET /api/reviews：产品/方面/情感/关键词/状态/分页筛选。
- PATCH /api/reviews/:id/correction，GET /api/reviews/:id/history：复核与历史。
- GET /api/products/:id/stats：有效或 pure=true 原模型统计。
- GET /api/compare?ids=a,b：2～3 产品对比。
- POST /api/imports/preview、POST /api/imports/commit：校验预览和提交。
- GET /api/batches、GET/POST /api/jobs：批次与任务。
- GET /api/export：导出筛选意见与未涉及方面的评论。

统一业务错误结构由 Nest 提供 statusCode/message/error；参数错误 400、未登录 401、未知对象 404、限流 429。请求体上限 6 MB，CSV 内容额外限制 5 MB。
