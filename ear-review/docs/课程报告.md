详细的数据获取候选、两类 CSV 的区别、模型训练公式、实际推理路径、资源清单和从零开发步骤，见同目录[NLP原理与数据](NLP原理与数据.md)。这部分应作为最终报告的方法与实现附录，或并入第4～6章。

模型权重、运行设备、训练及指标的完整记录见 [模型运行训练与测试](模型运行训练与测试.md)；模型和语言/技术选择理由见 [模型与技术栈选型说明](模型与技术栈选型说明.md)。新增文档可分别作为实验附录与选型依据，不将未执行实验写成报告结果。

## 摘要

本项目针对耳机评论包含多方面且情感不一致的问题，开发了使用 TypeScript 的本地 Web 系统。系统支持本地预训练文本模型结构化抽取，以字符 n-gram 朴素贝叶斯和领域规则为基线对照，服务器校验真实原文证据。前端使用 Vue 3，后端采用 NestJS，SQLite 保存评论、预测、批次与人工修订，Worker 执行批量计算。系统以整批评论分析为主，支持CSV导入、本地模型分类、正负反馈总结、六方面可视化、原文复核及结果导出；单条分析为辅助试用。软件核心与浏览器流程经自动化测试验证。教学检查集用于验证方法和展示过程，不用于证明真实消费者数据上的泛化能力。

关键词：自然语言处理；方面级情感分析；TypeScript；软件工程；评论分析。

## 1. 项目背景与可行性

整条评论可能同时表达“音质好”和“戴久了疼”。若只给整条文本打一个正负标签，会丢失对具体产品方面的意见。本项目将评价组织为“方面—情感—原文证据”，让用户进一步查看产品分布和评论依据。

开发约束来自三人课程大作业与全 TypeScript 要求。采用本地文本模型语义模式和可训练传统基线；模型下载后可本地推理，不依赖付费在线API，速度和内存需求仍需实测。团队职责建议为前端、后端、NLP 三条主线，但实际成员贡献须由团队如实填写。

技术可行性已通过本地构建和运行验证。数据可行性仍有限：当前没有取得真实耳机方面级独立标注集，因此采用明确标注的教学语料，同时提供授权数据导入与外部标注训练入口。

工程方法参考 [SWEBOK 官方知识体系](https://www.computer.org/education/bodies-of-knowledge/software-engineering)，围绕需求、设计、构建、测试和维护组织。需求表达参考 [ISO/IEC/IEEE 29148 公开介绍](https://www.iso.org/obp/ui?_escaped_fragment_=iso%3Astd%3Aiso-iec-ieee%3A29148%3Aed-2%3Av1%3Aen)，质量要求参考 [ISO/IEC 25010:2023 官方摘要](https://www.iso.org/standard/78176.html)。本报告不宣称进行了完整标准符合性认证。

## 2. 需求分析

### 2.1 用户需求

浏览者需要理解具体方面的意见分布，并可回到原文核对；管理员需要检查数据、运行任务和修正错误。教师验收需要可运行系统、真实实现机制、可复现测试与清楚的功能边界。

固定六项方面为音质、降噪、佩戴舒适度、续航、通话与游戏延迟。一条文本可涉及多方面；未提及不补标签，无法可靠归属的意见显示待复核。正面、负面、中性、混合分别展示。

### 2.2 功能与非功能要求

FR-01～FR-08 分别覆盖产品与权限、CSV 导入、分析任务、方面情感与证据、浏览与复核、产品画像、需求对比、结果导出。完整规格、输入输出、异常和对应测试见同目录[开发指南](开发指南.md)。

非功能要求包括本地可运行、严格 TS 类型检查、事务与唯一约束、真实证据索引、后端鉴权、密码哈希、上传限额、公式转义、任务重启处理和响应式布局。

系统不处理电商交易、登录授权采集、语音图片、开放式聊天或真实性能测评。当前数据与实验重点是中文耳机评论，其他语言效果未验收。需求预设仅筛选相关评价维度，不声称从用户评论推断全部使用场景。

### 2.3 用例与验收

主要用例为导入并分析、查看画像与比较、管理员复核。验收需要证明正确输入可以完成流程，非法输入不会污染数据，复核结果不会覆盖原预测，画像分母和原文依据可核对。方案中的算法与性能数字是目标，需和本报告实测范围区分。

## 3. 总体设计

系统采用 B/S 架构，浏览器运行 Vue 单页应用，NestJS 提供 REST API 和构建后静态页面。业务服务编排用例，六类 Repository 封装领域 SQL，SqliteDatabase 管理连接/事务，database-bootstrap 管理迁移；Store 提供仓储组合与兼容转发；Worker 运行独立 NLP 计算并发送结果给主线程保存。

前端按评价总览、产品画像、产品对比、评论导入、平台采集组织。首页以整批评论的正负反馈和六方面分布帮助用户了解耳机；CSV导入与公开采集负责接入数据，单条分析降为页脚辅助试用。

本版本对方案进行轻量裁剪：Vue 响应式状态代替额外状态库，自定义表单和可读堆叠条代替组件/图表库，Node 内置 SQLite 代替 Prisma。数据库和算法功能仍实际运行。裁剪依据是本地可携带性和减少依赖，报告不得将未使用的方案库写成实际实现。

## 4. 详细设计

### 4.1 数据与版本

数据库保存 products、batches、reviews、predictions、corrections、jobs、admins、job_errors、collections。评论用产品和外部 ID、产品和文本指纹分别建立唯一约束；预测用评论 ID 和模型版本组成主键；修订另表追加保存。批次记录来源与校验概要，任务记录状态、进度和错误；job_errors 保存逐条失败原因。

统计采用每条评论最近成功预测，叠加其版本的最新人工复核；可能混用方法，页面注明。用户勾选纯模型视图时不应用复核，从而避免把人工修订当作模型成绩。旧预测保留，新版本失败时旧成功结果仍展示；导出记录实际结果版本，不误标为最新模型。

### 4.2 NLP 流程

新增 semantic 模式由TypeScript调用本机Ollama，传完整评论、方面任务提示及JSON schema，预训练Qwen3输出情感、表达方式、强度、理由和证据；服务器校验原文子串，对歧义及缺正负证据的mixed转待复核，错误不降级。已在固定42条合成检查集实际比较纯MNB、hybrid、rules和Qwen3，结果与失败记录见[模型对照实验报告](模型对照实验报告.md)；真实消费者数据效果未验证。下述为保留的基线流程：

方面级任务定义参考 [SemEval-2014 Task 4 原始论文](https://aclanthology.org/S14-2004/)。本系统限定固定类别定位与情感分类，证据为相关子句，不宣称开放提取所有方面术语。

原文首先按标点和转折切分，切分保留 UTF-16 偏移。方面词典判断每个子句涉及的方面。通话/游戏中的“声音”通过领域规则避免被机械地另算音质。随后提取字符 1/2/3-gram 和方面标记，用加一平滑多项式朴素贝叶斯产生局部情感候选；明确规则优先修正候选，未覆盖规则时使用模型。低分差或共享意见难归属时待复核。

同一方面同时存在正负局部意见时汇总为混合。一条评论同一方面在产品统计中最多计一次。证据在客户端高亮时直接用输入原文 slice(start,end)，既可验证真实性，也避免清洗后索引错位。

### 4.3 统计与对比

已判定数 N = 正面+负面+中性+混合；正面占比为正面/N。待复核、未提及不进入 N；N=0 以 null 表示，避免用 0% 误导。少于 20 条提示样本不足，这个阈值不代表显著性检验。

对比要求 2～3 款产品，需求预设仅突出对应维度。界面同时显示样本数、负面数、待复核数量和原文；不强制生成总排名。

### 4.4 任务与错误设计

CSV 经校验预览后产生短期标识，提交阶段重新确认标识有效性并在事务中保存。重复提交被拒绝，数据库唯一约束处理并发重复。Worker 批量分析写入评论/版本复合主键，成功任务再次创建返回原任务；失败允许重试。重启后未完成任务改为失败并显示恢复提示，已完成数据保持。

认证使用 scrypt 密码哈希、随机初始密码和短期 Bearer 会话。未经登录的写接口由服务器拒绝。伪造证据、错误方面、文件超限和未知产品有明确错误返回。

## 5. 系统实现

### 5.1 工程结构

apps/web/src 实现 Vue 页面、API 客户端与分析、证据、评论和字段映射组件；apps/api/src 实现 HTTP Controller、业务 Service、领域 Repository、Auth、数据库初始化和 Worker；packages/contracts 提供共享枚举与结构；packages/nlp 提供训练、预测、切句、规则与意见汇总；scripts 提供模型导出、教学评估和轻量性能测量。

所有业务代码、训练与评估脚本为 TypeScript，使用 tsx 开发、tsc 编译服务器、Vite 构建客户端。package-lock.json 固定实际依赖版本，构建先运行后端 tsc 与前端 vue-tsc 类型检查。

### 5.2 实际数据与模型

预置三个虚构产品、36 条人工教学评论。训练语料为 126 条人工编写的正负中性例子；检查集为 24 条与训练完整文本不同的独立人工编写例子。检查集包含多方面、否定、转折、混合、emoji、中性功能描述及无关物流/客服文字。

基线模型版本为 mnb-8a862b69。本地语义版本包含模型标签与当前提示版本absa-v4（42条模型对照为历史absa-v2，首轮absa-v1归档），使用模型提供方的预训练权重，项目没有微调；本次实测digest与硬件记录见模型对照实验报告。模型文件含词表、类别频数与样本数，服务启动读取校验；训练命令可使用另行标注的授权训练 CSV。页面显示模型和数据类型，评价文件版本不匹配时不继续展示旧成绩。

### 5.3 核心实现证据

analyze() 与 splitClauses() 实现方面定位和偏移保存；predict() 使用真实频数学习而非固定返回值。store.importRows() 事务导入并保存校验概要；savePrediction() 采用版本化 upsert；review() 根据是否 pure 应用修订；stats() 使用评论/方面计数。AnalysisJobService.pump() 启动 Worker，并通过 JobRepository 记录状态；单条与批次经统一 AnalysisEngine 调用模型。

前端以 AnalysisResult 表示六项判断，EvidenceText 按真实索引高亮。CSV、单条分析、复核、对比和导出均调用实际后端接口，不是静态展示。

## 6. 系统测试与 NLP 评价

### 6.1 环境与功能验证

实际运行环境为 Windows、Node v24.14.0、Intel Core Ultra 9 275HX、系统报告约 31 GiB 内存。该设备强于方案假设的普通 8 GB 电脑，不能把本次时延外推到所有设备。

当前核心测试共46项，覆盖公开采集、总结口径、按链接建耳机、原生Chrome/CDP读取、自动翻页与登录配置持久化夹具，以及语义输出纠错重试与拒绝伪造证据。早期基线检查包括：11项基线NLP、5项存储、3项启动、3项CSV映射、3项语义协议/校验、1项纯MNB规则隔离、1项对照指标错误与拒判口径。语义部分使用模拟返回，不评价实际模型能力；覆盖多方面、转折、否定、中性、混合、待复核、通话归属、emoji 原文索引、模型序列化、重复导入、统计、复核分离及重新打开数据库。

端到端共十三个场景，新增最新/历史任务区分与已尝试进度展示；同时覆盖用户首页、平台受限状态、新耳机按链接直接采集、辅助浏览器CSV衔接、真实文件上传/中文列映射/自动编号/画像、语义服务不可用不降级/长文不截断/逐条失败保留、桌面分析与移动布局、画像与需求对比、API鉴权/校验/任务幂等/复核/导出、管理员页面导入分析与修订导出。测试使用独立3002端口和独立数据库，避免修改3001演示数据。最终运行结果应以output/playwright/results.json及最近控制台记录为准。

### 6.2 教学检查集结果

24 条教学检查例子中，方面 micro-F1 为 1.000，端到端“方面—情感”micro-F1 为 0.98305，TP=29、FP=0、FN=1。纯规则与混合模型在该集的结果相同，不能据此声称混合模型优于规则，也不能将样例结果写成真实领域准确率。

错误例子为“充电太慢，但音质很好听。”：续航方面产生负向候选，但最终为待复核，端到端评价计为漏判，不将拒判样本排除以提高成绩。评价文件保留全部错误和各类支持数。

尚未完成真实领域双人标注一致性实验、冻结真实训练/验证/测试划分、独立情感分类宏 F1 和跨型号泛化实验。报告将其列为未验证事项，而不是用当前检查集替代。

### 6.3 性能冒烟测量

36 条评论数据库中，对 12 条评论产品画像执行 100 次已预热查询，并发为 10，p95 约 7.03 ms，失败数 0。进程内连续分析 1000 条短合成文本约 111.31 ms。

进程内时长不包含 HTTP、数据库与 Worker 调度；当前数据库也未达到 5000 条。因此本次只证明小规模本地流程运行顺畅，不宣称完成全规模性能验收。机器规格、数据规模、次数与测量方法保存在 output/benchmark.json。

## 8. 总结与局限

系统完成了围绕 NLP 输出的可运行教学闭环，能够从评论输入走到方面判断、原文核对、统计比较和人工修正。开发与测试证据能够对应需求规格，页面不是预制结果的静态图。

主要局限为教学语料规模小、规则适配范围有限、复杂意见归属与反讽易失败、没有真实独立领域测试、尚未验证普通设备和更大数据库性能。本地Qwen3预训练权重部署与GPU推理、MNB自行训练及固定合成检查集对照已完成。首轮全部拒判的缺陷和状态提示修正后的同集复测分别保留；独立真实语义效果评估仍未完成。SQLite 内置 API 在当前 Node 版本会显示实验性提示；本地系统不是完成公网安全验收的产品。

后续工作应优先获得授权真实评论，完善标注规范与一致性检查，建立冻结独立评估集，完成已接入的预训练模型部署和真实语义评价。平台匿名公开采集已增加入口及真实错误处理，但本次两平台探测均受限，没有实际采集数据；登录授权接口、真实领域评价及多用户隔离仍需另行实施。

辅助采集采用原生Chrome与Playwright CDP连接，专用配置目录保留登录态。正常登录后自动读取/去重/尝试翻页并生成CSV，也可手动读取。无需扩展和配对码，写接口仍需管理员登录。真实原生Chrome的受控夹具验证读取、自动翻页及配置保存；Chrome实站在用户正常登录后采集了华为FreeClip 2的50条真实评论，自动滚动加载并去重、保存CSV，任务completed。该有限样本不代表全量评论或总体好评率，正式导入与模型分析状态以工作台当前任务为准。详见[真实数据与浏览器辅助采集](真实数据与浏览器辅助采集.md)。


平台采集补充验收：隐藏/延迟评价入口需等待，未能打开完整评价弹窗时提示且保留浏览器，不静默读预览后报完成。未达到设定数量的提前停止显示部分采集，保留可下载CSV；数量显示实际/设定。2026-10-14华为和小米两个商品分别实测50/50条成功，完整记录见真实数据与浏览器辅助采集报告。


自动化主流程：填写商品与目标条数，点击打开Chrome即后台采集，系统自动打开完整评价、滚动/翻页和去重、保存CSV；登录/验证后自动继续，无须逐页操作或第二次开始。自动等待最长5分钟，加载最大100次、数量最大100条；无更多数据则保留部分结果。具体实测见打开即自动采集实测记录。
