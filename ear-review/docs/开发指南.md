# 开发指南

本文集中记录实际项目的需求、架构、接口、配置和开发约定。本版本新增本地 Ollama 文本模型接口、CSV 字段映射/编码与逐条错误追踪；已完成本地权重部署及固定合成检查集对照，结果见[模型对照实验报告](模型对照实验报告.md)，真实领域泛化仍未验证。启动命令见[项目 README](../README.md)，算法与数据见[NLP 原理与数据](NLP原理与数据.md)，报告见[课程报告](课程报告.md)。

运行与训练实验集中在 [模型运行训练与测试](模型运行训练与测试.md)；选择依据集中在 [模型与技术栈选型说明](模型与技术栈选型说明.md)。实现说明及实际对照实验报告也集中在本目录；数据和逐条结果放在实验结果子目录。

## 环境与目录

Node.js >=24.14.0；npm 随 Node.js 安装。双击 `安装环境.bat` 可自动准备缺失环境，已有 Node 时运行 `npm run setup`。脚本从 `package-lock.json` 校验依赖、按源码指纹判断是否重新构建，并生成 `requirements.txt`；后者是可读的 Node 环境清单，不供 pip 安装。

`apps/web` 为 Vue 前端；`apps/api` 为 NestJS 服务；`packages/contracts` 为共享类型；`packages/nlp` 为模型和规则；`scripts` 为安装、启动、训练和测试辅助；`data` 保存教学数据和基线模型；`docs` 保存开发、数据、实现、模型实验、选型和课程报告。Qwen3权重由独立Ollama目录管理。

`data/runtime` 保存数据库、随机初始密码和启动日志，不提交 Git；`output` 和 `test-results` 是可重新生成的临时结果；`dist` 与 `node_modules` 由安装/构建命令生成。不要删除正在使用的数据库或把运行密码提交到仓库。

环境安装依赖 Windows 的 [WinGet 安装命令](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)；只安装 Node.js LTS，其他项目依赖由 npm 管理。首次系统安装可能需要操作系统权限确认。浏览器测试可额外执行 `npm run setup:tests` 安装 Chromium；已安装 Chrome 时自动使用 Chrome。

## 配置与启动排查

复制 `.env.example` 为 `.env` 可设置 PORT（默认3001）、DATA_DIR（默认data/runtime）、MODEL_PATH（默认data/model.json）、OLLAMA_URL（默认http://127.0.0.1:11434）、OLLAMA_MODEL（默认qwen3:4b）、OLLAMA_EXE（默认tools/ollama/ollama.exe）、OLLAMA_MODELS（默认../模型权重）。便携启动器会将OLLAMA_MODELS传给其启动的Ollama进程，已有独立服务需自行核对存储位置。安装和模型下载见README，npm安装器不安装Ollama或权重。ADMIN_PASSWORD 仅首次创建数据库时生效，不会覆盖已有管理员密码。

管理员会话八小时过期，服务重启后需重新登录。访客无需登录即可单条分析、浏览画像和对比；写入、复核与导出由后端鉴权。

启动器先准备环境，然后等待健康接口再打开默认浏览器。已有服务直接复用，其他程序占用时提示修改 PORT；浏览器打开失败会打印访问地址并写 `data/runtime/launcher.log`。启动器窗口保留运行，Ctrl+C 停止；终端中的 SQLite 实验性提示不是启动失败。

## 开发协作

按前端、后端、NLP 三条线分工，共同维护 `packages/contracts` 的方面/情感枚举、证据索引和任务状态。接口变更同时更新调用方与测试。

使用 feature 分支和 Pull Request 合并；提交前至少运行 `npm run typecheck` 和 `npm test`，涉及页面流程时运行 `npm run test:e2e`。不要提交依赖、构建、运行数据库、密码和临时测试产物。

## 1. 业务目标与系统边界

普通浏览者通过评论中的具体方面理解耳机优缺点；管理员维护产品、导入评论、运行分析并修订错误。核心能力为固定六方面识别、完整上下文语义抽取或基线局部分类，以及原文证据校验。系统不执行真实声学测评，不进行电商交易或开放式问答；平台采集仅尝试匿名公开评论，不具备登录授权或全量采集能力。

六个方面：音质 sound、降噪 noise、舒适度 comfort、续航 battery、通话 call、游戏延迟 latency。

## 2. 功能规格与追踪

FR-01：访客只读浏览，管理员使用账号密码登录后执行写操作；创建和编辑产品。输入为产品 ID、名称、说明；重复 ID 和非法 ID 返回 400，未登录写操作返回 401。对应 Auth、Products 接口；端到端测试“API 鉴权”及“管理员页面”验证。

FR-02：输入 UTF-8/GB18030 CSV 与来源说明，识别列后可人工映射，正文必填；编号可生成、产品可统一指定集合。预览有效/错误/重复行，最多5000行、5MB、每条5000字；基线分析超过1000字失败但不截断。产品不存在、空评论、缺列和错误引号不静默接收。确认后事务提交有效非重复记录；持久化批次校验数量与拒绝行原因。对应 Imports、Store；存储去重测试及 API 导入测试验证。

FR-03：单条分析不写正式统计；批次分析持久化任务状态并由 Worker 执行。任务正常状态 queued → running → completed，异常变 failed；重复请求已有成功/运行任务返回原任务；失败可建立新的重试任务。重新启动时未完成任务改为 failed 并提示原因。对应 AnalysisJobs；Worker 端到端、幂等和重启测试验证。

FR-04：输入中文文本，输出方面、正面/负面/中性/混合、classified/review 状态、证据和版本。每条证据必须为原文子串，索引为 UTF-16 左闭右开。未提及不生成预测；多方面意见难以归属时待复核。对应 Nlp 和 AnalysisResult；11 项 NLP 单元测试及桌面原文定位测试验证。

FR-05：按产品、方面、情感、关键词、待复核/已复核筛选，8 条一页。管理员修订方面与情感时填写真实原文证据和理由。修订不覆盖预测，历史保存 actor/time/reason。对应 Reviews、Corrections；存储有效/纯模型视图、API 伪造证据拒绝、浏览器复核测试验证。

FR-06：每个方面统计正面、负面、中性、混合、待复核与修订数。同评论同方面最多计一次。N=正面+负面+中性+混合，正面占比=正面/N；N=0 为 null，N<20 提示样本不足。待复核和未提及不进入 N。对应 Statistics；混合计数、空数据和修订一致性测试验证。

FR-07：选择 2～3 个产品比较同一维度评价与原文。通勤突出 noise/comfort，游戏突出 latency/sound，长时佩戴突出 comfort/battery；全部模式显示六项。缺失数据不填零，不生成总排名。对应 Comparison；产品画像/需求对比浏览器测试验证。

FR-08：管理员导出筛选结果。CSV 包含来源、教学标记、方面、状态、证据、模型版本和修订标记。没有方面的评论在未指定方面筛选时保留空方面行；类公式单元格前置单引号，防止表格软件执行。对应 Exports；API 和浏览器下载测试验证。

## 3. 关键用例

### UC-01 导入与分析

参与者：管理员。前置：已登录，产品存在。

主流程：准备 CSV → 填写来源和教学标记 → 校验预览 → 确认有效记录 → 事务入库 → 创建任务 → Worker 分析 → 保存预测 → 显示完成状态。

替代/异常：文件超限或格式错误直接拒绝；错误与重复行跳过并记录；没有有效行不可提交；预览过期需重做；分析失败可重试；成功提交后不能重复使用预览标识。

后置：评论、批次、校验概要、模型版本预测和任务进度可以查询。

### UC-02 看画像与对比

参与者：浏览者。前置：产品存在。

主流程：选产品 → 看六方面分布 → 点击方面筛选 → 看高亮原文 → 进入对比 → 选至少两个产品 → 选择需求 → 展开证据。

异常：无评论时显示空数据；少于 20 条提示样本不足；选择数量不足时提示补选。后置：用户知道结论对应的评论数量及原文，系统不代替真实测试。

### UC-03 人工复核

参与者：管理员。前置：评论已分析。

主流程：打开复核 → 选方面与情感 → 填写原文真实子串及理由 → 保存 → 原预测保留 → 有效画像与对比刷新。

异常：无权访问返回 401，虚构证据/非法标签返回 400。后置：修订可追踪，纯模型统计不改变。

## 4. 非功能规格

- 可运行性：Node 24.14、Windows、本地浏览器；依赖锁定，构建通过严格 TypeScript 检查。
- 可靠性：参数化 SQL、外键、事务和唯一约束；任务持久化；旧完成结果重启后保留。
- 安全性：随机初始管理员密码，scrypt 哈希，会话八小时过期；后端检查写权限；评论按文本渲染；上传限额；登录/分析限流；CSV 公式转义。
- 可用性：四个主入口、清楚的表单标签、正负情感文字、原文高亮、加载/错误/空数据状态；390px 移动布局与桌面布局验证无横向溢出。
- 性能：当前仅完成小规模冒烟测量；5000 条数据库、不同普通电脑及端到端千条批次尚未作为已达标结论。

## 5. 详细设计

### 5.1 分层与调用

Vue 页面使用共享 contracts 调 REST API；Nest Controller 完成鉴权、参数验证和编排；Store 管理参数化 SQL/事务；Node Worker 调用 NLP 模块执行批次计算，再由主线程回写数据库。单条基线直接执行，语义请求异步调用Ollama；批次串行调用本地服务。

前端组件：App 管理路由对应页面与业务状态；AnalysisResult 展示六方面与选择高亮；EvidenceText 根据索引拆分原文；ReviewList 展示筛选结果及复核表单。请求序号防止旧查询响应覆盖新的产品选择。

### 5.2 数据字典与约束

products：id 主键，name/subtitle/source；产品名与说明可修改，ID 固定。

batches：id 主键，name/source/created_at/summary。summary 保存提交数、入库数、错误数、重复数与拒绝行原因。

reviews：id 主键，product_id 外键，external_id，text，fingerprint，source，synthetic，batch_id 外键。唯一约束为 (product_id,external_id) 与 (product_id,fingerprint)。fingerprint 由 NFKC、空白归一及 SHA-256 生成，原文不改写。

predictions：复合主键 (review_id,version)，result 保存完整 Analysis JSON，含证据偏移和语义理由；updated_at 决定最近成功版本。重试对同一版本 upsert，统计不重复累计。默认查询每条评论最近一次成功预测，修订仅应用该结果版本；不同方法可能混用，页面明确提示，正式方法比较须隔离统一分析。

corrections：id、review_id、version、aspect、result、reason、actor、created_at。按顺序应用该版本最近修订；原预测仍存在。

jobs：id、batch_id、status、total、processed、error、version、created_at。单实例 Worker 逐任务逐评论处理；单条失败记录 job_errors(job_id,review_id,message)，其余继续。processed是已尝试数，不是成功数；完成且有失败则任务failed并显示数量。数据级幂等保证重试安全。

admins：username 主键、password_hash（salt:hash）。会话保存在服务器内存中，重启即失效。

数据库用 WAL，索引覆盖批次查找与复核查找。初始化兼容旧库并补充 summary 列。Schema 不支持产品删除，是本版本有意保留的数据追溯边界。

### 5.3 算法

semantic 模式通过 packages/nlp/semantic.ts 调本地 /api/chat，任务提示+JSON schema 输出固定方面键、情感、表达方式、强度、理由和原文片段spanId；服务器还原对应原文证据。服务器检查标签、重复方面和证据子串，mixed必须含正负证据，不确定转review。Qwen3是预训练推理，没有项目微调；协议测试不代表真实模型效果。基线如下：

多项式朴素贝叶斯使用字符 1/2/3-gram 频数，训练方面标记与局部上下文。类别为 positive/negative/neutral，采用加一平滑。

每类对数分数为 log P(c) + Σ count(feature) × log((类别内频数+1)/(类别总频数+词表大小))，选择最大分数。模型保存词表、类计数、样本数、来源类型与数据哈希版本。模型文件读取时检查版本格式、计数与类别有效性。

混合系统先计算 MNB 候选；明确领域情感规则优先校验。规则不覆盖时采用模型，分类分差小于 3 的未知表达进入待复核。分差只是当前教学拒判启发式，未用真实验证集校准，不能称作正确概率。

转折词将意见分开；同方面既有正面又有负面时汇总 mixed。复杂同句共享意见或无法归属进入待复核。证据是完整相关子句，不宣称达到了精细方面词级开放提取。

### 5.4 接口列表

- GET /api/health、GET /api/model：健康、模型与当前版本教学评价。
- POST /api/auth/login，GET /api/auth/me，POST /api/auth/logout：管理员会话。
- GET/POST /api/products，PATCH /api/products/:id：产品读取、创建与修改。
- POST /api/analyze：mode=semantic/hybrid/rules；semantic最长5000字，其余1000字；本地模型错误503，不静默降级。
- GET /api/reviews：产品/方面/情感/关键词/状态/分页筛选。
- PATCH /api/reviews/:id/correction，GET /api/reviews/:id/history：复核与历史。
- GET /api/products/:id/stats：有效或 pure=true 原模型统计。
- GET /api/compare?ids=a,b：2～3 产品对比。
- POST /api/imports/columns：表头、自动映射、前3行；POST /api/imports/preview 接收 csv/mapping/productId/source/isSynthetic；POST /api/imports/commit 提交有效行。
- GET /api/batches、GET/POST /api/jobs：批次与任务，创建时可传mode=semantic；GET /api/jobs/:id/errors 查询逐条失败原因。
- GET /api/export：导出筛选意见与未涉及方面的评论。

统一业务错误结构由 Nest 提供 statusCode/message/error；参数错误 400、未登录 401、未知对象 404、限流 429。请求体上限 6 MB，CSV 内容额外限制 5 MB。

## 6. 未验证或未实现事项

未获得真实方面级标注数据；未实现 BERT/ONNX 增强、登录授权平台采集、自然语言场景推断、管理员公开注册、OpenAPI 自动文档、公开部署、5000 条规模性能验收。规则覆盖与 MNB 真实泛化需进一步实验。

本地 SQLite 使用 Node 24.14 内置 API，会有实验性提示。长期生产使用应另行验证或替换数据适配层。

## 界面约定

浅色操作界面，顶部四个任务入口。评论分析页并列输入与结果，窄屏上下排列；原文证据是重点。背景 #f5f6f3、正文 #24372f、主操作 #28614e，使用中文系统字体。

绿色正面、红色负面、灰色中性、褐色混合，各状态同时显示文字。保留表单标签、键盘焦点、加载、错误和空数据提示；图表显示计数与分母。产品展示以可追溯评论为依据，不制作营销式大标题或无证据总排名。

## 后续开发优先级

优先获取授权真实评论、完善标注一致性和独立划分，再评价规则/MNB 和可选增强模型。初始目标为方面 micro-F1≥0.80、端到端方面情感 micro-F1≥0.70，但尚未在真实数据上验收。新增功能应维持“需求—模块—接口—测试”追踪，不把教学检查集成绩当领域能力。

报告提交前补齐成员真实贡献、当前版本测试结果与重新采集的页面截图。原来分散在“方案”的需求边界、团队协作、验收口径和报告结构已汇入这三份文档，不再保留旧任务计划与工具日志。

## 用户批量分析与公开采集改造（2026-10-13）

首页/为评价总览，/data为评论导入，/collect为平台采集，/products保留详细原文与复核，/try为辅助单条试用。导入页面默认没有教学CSV内容，批次默认选择本地文本模型，不自动降级。原文不足和模型请求失败通过任务记录处理。

FR-09：登录用户选择平台，提供具体商品链接/编号即可创建公开采集任务；目标耳机可选已有记录，或留空按链接自动创建。名称取用户填写的耳机名称；页面还可使用搜索词，均未提供时用平台商品编号，不假称已读取官方商品型号。关键词只打开平台搜索，不实现后台自动商品搜索或自动核实型号。每次1～100条，最多10页，页间隔1秒，单请求12秒超时。匿名方式的目标URL仅解析商品ID，实际请求固定平台域名且禁止跟随重定向。浏览器方式使用持久化采集专用Chrome，正常登录后可自动读取并翻页，也可手动翻页读取。解析JSON或JSONP但不执行脚本；保留商品编号、评论ID、正文、时间及来源，不采集昵称。响应不符合评论结构或访问受限时blocked，已取得部分数据再失败时partial，不生成替代样例。CSV可下载或载入现有导入预览。

FR-10：评价总览显示正负反馈、样本数、混合与待复核，按方面反馈数量列前三项及原文。总结是分类后的统计和证据摘录，没有额外生成未经证据支持的优缺点。仅纳入classified意见，mixed单列分布；纯模型/修订结果口径一致。

新增接口：

- GET /api/products/:id/summary?pure=true：当前版本的正负反馈及证据，公开只读。
- POST /api/collections：需要登录；body为platform（jd/tmall）、url、limit，可选productId或productName。未传productId时按平台与商品编号生成稳定ID，在事务中建立产品和采集任务；重复提交复用产品。
- GET /api/collections：需要登录；查看最近30条采集记录。
- GET /api/collections/:id/csv：需要登录；下载实际取得的CSV。
- GET /api/collections/:id/data：需要登录；将CSV及归属载入导入预览。

SQLite新增collections表：id主键，product_id外键，platform、item_id、url、status、requested、total、error、csv、created_at、updated_at。采集状态为running/completed/partial/blocked/failed，重启后未完成任务标失败。一时只执行一个采集任务；采集不会直接写reviews或启动分析，用户确认导入后复用batches/jobs流程。CSV以TEXT保存，小规模上限100条；该设计不用于大规模抓取文件归档。

匿名端点为club.jd.com的productPageComments.action及rate.tmall.com的list_detail_rate.htm，属于可变公开页面接口，不是已获授权的官方开放API。2026-10-13实际探测京东HTTP444、天猫非评论数据，成功获取0条；记录在output/collection-public-probe.json。解析单元测试用构造响应，浏览器受限状态测试用模拟，不宣称已采集真实耳机评论。

采集页在进入页面、窗口重新获得焦点和点击刷新时拉取最新耳机列表，并同步到首页/导入页。按链接新建后自动选中；更换链接时取消刚才自动选择的归属，避免将另一商品采到旧耳机中。带追踪参数的详情链接被归一为标准商品URL，参数不影响商品ID。

## 真实数据与浏览器辅助采集


collections新增method字段public/browser及waiting状态；生产使用原生Chrome加Playwright CDP连接，并保留data/runtime/chrome-collector-profile专用配置目录的登录态。POST /api/collections打开采集专用Chrome；POST /api/collections/:id/read手动读取当前页；POST /api/collections/:id/auto后台读取、去重、尝试翻页并保存CSV；POST /api/collections/:id/finish结束手动采集。所有写接口均需管理员登录。无需扩展或配对码；此前的pair/visible接口已删除。首次登录/验证需用户正常操作，不能复制日常Chrome的Cookie或绕过验证。最多100条/10页，找不到下一页或没有新评论时停止，失败保留已得数据。关闭采集专用窗口不关闭用户日常Chrome。实现与实站探测见真实数据与浏览器辅助采集报告。

自动采集状态：达到设定条数为completed；提前停止且已有正文为partial，界面显示实际/设定数量并继续允许下载CSV。完整评价弹窗未能打开时保持waiting与窗口，提示正常打开评价后重试。隐藏或延迟出现的评价入口会等待可见项，不静默将预览作为完整采集。修复实测见真实数据与浏览器辅助采集报告。


创建浏览器采集任务后自动启动：autoRunning表示后台仍在执行或等待登录/验证，完成正常登录返回对应商品页后自动继续，最多等待5分钟；不需第二次调用auto/read。目标条数决定加载上限，最多100条、100次加载。无更多评论时保留实际数量并标部分采集。

## 评价总览与任务界面（2026-10-14）

评价总览新增 SVG 环形图：汇总六个方面的正面、负面、中性及混合评价，图中分母为已判定方面评价数量。一个评论可同时涉及多个方面，因此总量不能称为评论条数；未提及及待复核不计入占比。六方面条形图使用相同的颜色与图例，保留正负反馈的原文依据。
