# 模型运行、训练与测试

核对日期：2026-10-13。本文以源码、已下载权重、GPU加载记录、MNB训练及实际同输入对照为依据。当前结果见[模型对照实验报告](模型对照实验报告.md)。数据获取与 CSV 格式见 [NLP 原理与数据](NLP原理与数据.md)，选型理由见 [模型与技术栈选型说明](模型与技术栈选型说明.md)。命令均在 ear-review 项目目录执行，另有说明的除外。

## 1. 项目到底使用了哪些模型

本项目有两个不同的模型，不能混写为同一个训练过程。

- 本地语义模型：默认 Qwen3-4B，通过 Ollama 的 qwen3:4b 标签调用。用途是读取完整评论，结构化抽取六方面情感、表达方式、强度、理由和原文证据。已下载到指定目录，通过便携Ollama v0.40.3实际运行；42条合成检查集及首轮/复测结果均留存。
- 自行训练基线：字符 1/2/3-gram 多项式朴素贝叶斯（MNB），结合方面词典和领域规则。训练、预测和教学评价均已有实际代码与模型文件；运行于 Node.js CPU。

semantic 为预训练文本模型推理；hybrid 为 MNB 加规则；rules 为规则决策对照。单纯改变提示词、设置 JSON schema、上传待分析 CSV 或人工修订结果，都不等于训练 Qwen3。系统没有图像/音频输入，不是多模态分析。

## 3. “模型权重多少”分别指什么

### 3.1 Qwen3 的参数数量

Qwen 官方模型卡将 Qwen3-4B 标为约4.0B参数的因果语言模型，其中非嵌入部分约3.6B；是约40亿参数的稠密模型。参数数量表示可学习数值规模，不是下载文件大小。[Qwen3-4B 官方模型卡](https://huggingface.co/Qwen/Qwen3-4B)。

本次核对 Ollama 的 qwen3:4b 页面显示4.02B、Q4_K_M量化、约2.5GB，页面短标识为359d7dd4bcda。本机实际清单确认4.0B、Q4_K_M，下载大小和完整digest见第2节；标签未来可能更新，实验按实际digest记录。[Ollama 对应版本](https://ollama.com/library/qwen3:4b)。

Q4_K_M 是量化方案，不能简单理解为所有参数恰好4位。按40亿参数粗算，全部FP16仅数值存储约8GB、FP32约16GB；这是理论估算，不是本项目下载文件或峰值内存测量。量化文件更小，但加载后的内存还包含上下文缓存、工作缓冲和服务开销；2.5GB文件不意味着2.5GB内存或显存就一定足够。

### 3.2 MNB 的模型规模

MNB 不存在4B之类的神经网络参数量。当前共享三分类器的训练计数为：

- positive：42条文档，特征累计频数1326，保存564种出现过的特征。
- negative：42条文档，特征累计频数1308，保存566种出现过的特征。
- neutral：42条文档，特征累计频数1344，保存523种出现过的特征。

三类共享1172个特征的词表。这些频数用于计算类别概率，不能直接称为1172个神经网络权重。六个方面标记参与输入，但不是六个分别训练的模型。mixed 是局部正负聚合结果，不是 MNB 的第四个训练类别。

## 4. 用什么运行，GPU 还是 CPU

### 4.1 Web 与基线运行时

浏览器运行 Vue 3 页面；后端运行 Node.js v24.14.0 / NestJS。TypeScript 在生产构建中编译为 JavaScript；开发、训练与评价脚本通过 tsx 执行。MNB 计数和预测由 Node.js CPU 完成，不使用 CUDA、PyTorch 或 Python。批次由 Node worker_threads 调用 NLP 模块；单个批次内逐条执行，不是GPU并行训练。

### 4.2 Qwen3 推理运行时

Qwen3 由独立的 Ollama 服务加载权重、分词并执行推理。TypeScript 只组织请求、处理任务并验证响应，不在 JavaScript 内自行计算40亿参数的矩阵运算。接口默认 http://127.0.0.1:11434/api/chat。

Ollama 可在CPU、受支持GPU或CPU/GPU混合模式运行，实际情况由硬件、驱动、可用显存、上下文和服务配置决定。当前代码没有显式设置 num_gpu；不能据此断言一定CPU或一定GPU。运行后用 ollama ps 查看 PROCESSOR 列：100% CPU、100% GPU 或混合比例。[Ollama 处理器检查说明](https://docs.ollama.com/faq#how-can-i-tell-if-my-model-was-loaded-onto-the-gpu)。

本机只读硬件查询结果：

- CPU：Intel Core Ultra 9 275HX（已有评价文件记录）。
- 物理内存：33,752,997,888字节，约31.44GiB。
- 独立显卡：NVIDIA GeForce RTX 5060 Laptop GPU。
- nvidia-smi 显存容量：8151MiB；NVIDIA 驱动592.01。

实际加载后的ollama ps显示100% GPU，context=16384，runner=llamacpp；/api/ps记录size_vram=5,098,103,111字节（首轮）。复测记录见实验JSON的device；整卡显存采样包含其他进程，不是隔离模型内存。最大可用批次规模未验收。Win32_VideoController 的 AdapterRAM 字段可能不能准确表示较大显存，本记录使用 nvidia-smi 的查询结果。兼容性和版本要求以 [Ollama GPU 文档](https://docs.ollama.com/gpu)及实际加载日志为准。

本项目默认 num_ctx=16384，长上下文会增加缓存占用；不要仅依据权重大小保证8GB显存一定能完整容纳所有请求。

## 5. Qwen3 是怎么训练的

### 5.1 模型提供方完成的训练

官方说明 Qwen3 系列经过预训练和后训练：大规模文本预训练建立语言能力，再通过长推理数据、强化学习及思考/非思考模式融合等后训练改善任务行为。系列预训练说明涉及约36万亿token、多语言文本、合成数学/代码及长上下文阶段；这属于提供方公开背景，不是本项目使用的数据量、训练时长或算力。[Qwen 官方训练介绍](https://qwenlm.github.io/blog/qwen3/)。

不能从上述系列介绍推导出本机Qwen3-4B的全部原始数据、精确学习率、epoch、训练GPU数量或最终loss。本项目没有复现这些训练，也没有保存对应训练日志；官方通用基准不能代替本项目中文耳机测试。

### 5.2 项目实际做的适配

packages/nlp/semantic.ts 使用固定任务提示描述六方面、否定、转折、比较、指代、隐含评价与反讽，提供 JSON schema，然后调用预训练模型。输出包含方面、情感、status、expression、intensity、rationale 和证据。服务器验证枚举、重复方面和证据子串，生成UTF-16位置；不确定或不完整mixed进入待复核。

当前配置：model=qwen3:4b，当前提示版本absa-v4（历史42条对照使用absa-v2，absa-v1首轮已归档）；think=false，temperature=0，stream=false，num_ctx=16384，num_predict=4096；最多两次结构化生成共用180秒截止时间，第二次仅用于输出校验失败后的纠错；服务/网络错误不按此重试。num_predict 是生成长度上限，不是训练步数；temperature 是解码设置，不是学习率。低温和 schema 旨在减少格式变化，不保证语义正确。官方非思考通用聊天建议与项目结构化抽取设置用途不同，本项目尚未完成解码参数效果对比。[结构化输出方法](https://docs.ollama.com/capabilities/structured-outputs)。

本项目没有对 Qwen3 做 SFT、LoRA、QLoRA、继续预训练、梯度更新或模型量化训练；所下载的量化产物由发布方提供。因此Qwen3“本项目训练loss、训练accuracy、验证loss、学习率、epoch”均为不适用，不应填0或编造曲线。

## 6. 项目自行训练的 MNB 怎么训练

### 6.1 数据与标签

packages/nlp/training-data.ts 保存126条开发时编写的教学合成样例（本次由助手撰写）：六方面各21条，每方面正/负/中性各7条。data/evaluation-cases.ts 保存另外编写的24条教学检查评论；36条演示评论不是该检查集。完整句子不相同仍不能说明独立采集，语料同源的偏差仍存在。

外部训练 CSV 必须已有人工真值：

```csv
aspect,text,label
sound,音质清晰,positive
comfort,戴久耳朵疼,negative
battery,支持无线充电,neutral
```

上面只说明格式，不足以训练；脚本要求每个情感类至少3条，外部数据必须有 --kind 来源类型。方面须为六个固定英文ID，标签须为positive/negative/neutral。星级、模型生成标签或人工复核不自动成为可靠训练真值。数据网站和获取边界见 [NLP 原理与数据](NLP原理与数据.md)。

### 6.2 学习步骤与公式

1. scripts/train.ts 读取标注CSV并验证标签与方面，或采用内置126条样例。
2. 对“方面标记 + 局部片段”小写化，去掉部分标点/空白，提取字符1/2/3-gram频数；不使用jieba、TF-IDF或词向量。
3. 按类别累计文档数Nc、特征频数count(f,c)及总频数Tc，只由训练数据建立词表V。
4. 预测时计算 P(c)=(Nc+1)/(N+3)，P(f|c)=(count(f,c)+1)/(Tc+|V|)。这是加一平滑。
5. score(c)=log P(c)+Σ count(f,x)×log P(f|c)，选最高分为候选；词表外特征不参与评分。
6. 写入模型JSON。最终基线规则可以覆盖候选或拒判，最高与次高分差小于3为当前启发式之一；分差不是校准概率。

没有反向传播、优化器或多轮epoch。频数累积是实际有监督学习，但不能套用深度学习训练曲线。当前训练入口没有自动划分、早停或自动调参，提供什么训练文件就使用什么文件。

### 6.3 可复现命令

默认命令会覆盖 data/model.json。需要保留现有模型时，使用单独输出：

```powershell
npm run train -- --output output/models/teaching-reproduced.json
npm run train -- --data data/authorized-train.csv --kind "授权真实训练集" --output data/models/real-v1.json
```

第二条只有真实文件已获取、标注并正确划分后才能执行，文件目前未提供。将 `.env` 中 MODEL_PATH 改为对应模型路径并重启，才会使用新基线。

## 7. 训练集、验证集、测试集怎样划分

当前已有内置训练集和教学检查集，尚未构建真实领域训练/验证/测试划分。建议团队取得授权数据后采用以下流程；这里描述的是待开展实验方案：

1. 保留原始评论ID、产品身份、来源、语言和文本，先去空值及近重复。
2. 制定方面/情感/证据/待复核规范，至少两名成员独立标注一部分样本，由第三人仲裁；记录一致性与歧义。
3. 按原评论和近重复组分割，不能让同评论不同方面片段分到训练和测试两边。可从70%/15%/15%起步，按型号/情感检查分布；这是建议比例，不是已执行划分。
4. 训练集学习MNB计数；验证集选择规则、拒判阈值、提示及解码设置；冻结测试集仅做最终比较。
5. 统一比较rules、hybrid、semantic；评论模型版本混用的产品画像不能直接充当方法评估。
6. 记录全部错误和拒判，不能仅统计模型愿意回答的样本，不能用测试集反复改提示后还称独立测试。

若要验证跨型号泛化，应保留型号隔离的测试划分；如果数据没有型号身份，就不能宣称跨型号性能。

## 8. 已有模型评价指标与含义

依据 data/evaluation.json（生成于2026-10-12；版本mnb-8a862b69），24条教学检查集上：

- 方面识别 micro-F1：1.0000。
- 端到端方面—情感 micro-F1：0.98305085。
- 方面—情感计数：TP=29，FP=0，FN=1；由此Precision=1.0000，Recall=29/30≈0.9667。
- 逐情感F1：正面1.0000，负面0.94117647，中性1.0000，混合1.0000；对应真值支持数12、9、7、2。
- 四类F1算术平均≈0.98529412，是根据保存结果推算的macro-F1；当前脚本未单独输出该字段。
- 保存的函数内推理p95：hybrid约0.5815ms、rules约0.1285ms；只有24条短样例，不含HTTP/数据库/Worker/Ollama，不能代表实际Web响应时间。

两个决策模式在该教学集的F1相同，不能宣称MNB增强优于规则。rules模式内部仍计算MNB候选，但不把无规则结果判为已分类；它是最终规则决策对照，不是完全不执行分类器的性能对照。

F1=2TP/(2TP+FP+FN)。方面评价检查是否找到正确类别；方面—情感评价检查类别和情感同时正确，情感错时可能同时产生一个FP和一个FN。classified之外的意见不进入已判定预测集合，但对应真值仍产生漏判，拒判没有从评分中悄悄删除。

保留错误：“充电太慢，但音质很好听。”的battery负面候选最终为review，计为FN；sound正面正确。不能把上述98.3%称为真实用户准确率，也不是纯MNB分类准确率、Qwen3成绩或训练集accuracy。

复现基线评价：

```powershell
npm run evaluate
```

命令写 data/evaluation.json，并使用当前已加载的MNB与固定教学检查集。换真实训练模型后仍不能因此声称测了真实测试集；当前评价脚本未提供外部测试集参数，也不评估semantic。

## 10. 安装后如何记录真实语义测试

### 10.1 模型、路径与设备记录


记录PROCESSOR和运行时显存，不将空载显存或显卡规格当作模型峰值。单次nvidia-smi只是快照，若要峰值需在整个实验期间采样。正式运行日志需保存在实验输出目录并把摘要与日期补回本文件。

### 10.2 单条实测与错误分析

服务运行在3001时，可直接验证接口；命令需要已安装并启动模型：

```powershell
$taskReview = @{ text = '降噪真厉害，地铁广播听得一清二楚，谢谢你。'; mode = 'semantic' } | ConvertTo-Json
Invoke-RestMethod -Uri http://127.0.0.1:3001/api/analyze -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($taskReview))
```

该文字是反讽候选测试样例，尚无本机实际预测结果，不预设模型一定正确。真实测试应包括直接评价、双重否定、隐含抱怨、不同方面相反、同方面情境冲突、反讽、比较、指代、无关物流、无明确评价和长评论，并与人工金标准对照。

需报告：方面/方面—情感micro及macro-F1；各情感和表达类型支持数；证据有效率和人工语义相关性；待复核率与拒判后的覆盖率；错误及请求失败率。只要服务器验证通过就写“证据语义正确”是不成立的，子串存在与证据支持结论是两种检查。

运行性能应区分首次加载与预热请求，记录端到端p50/p95、请求条数、字符/token规模、每秒评论数和实际CPU/GPU配置。不得用基线的亚毫秒计时替代生成模型时延。

## 11. 如果课程要求自己微调深度模型

当前实现包含真实MNB训练，但不包含深度模型微调。如果教师明确要求自行训练神经网络，需要增加独立实验流程，而不能把ollama pull描述为训练。

可选后续方向为带标注数据的中文编码器分类/方面模型，或对Qwen3做LoRA/QLoRA任务适配。前者更贴近固定标签分类，后者更贴近结构化生成；数据格式、资源和评估方法不同。它们都尚未实现。

届时通常使用Python训练生态，将训练工具作为独立子项目，Web仍可保留TypeScript，通过服务接口使用产物。必须额外记录数据划分、模型/分词器版本、随机种子、学习率、batch及梯度累积、epoch、优化器、精度、训练GPU、loss/验证F1、最佳checkpoint选择和冻结测试结果。本机约8GB显存不能据此保证某个4B微调配置一定可行，需要先做资源试验。
